# Mindmap 短命题添加

返回 [维护指南目录](README.md)。本指南仅描述后续操作，本次没有添加短命题。

## 1. 找到内容入口

当前 Mindmap 是思维树：一条句子对应一个可交互光点。短命题保存在 `thought-tree.js` 顶部的 `const thoughts = [...]` 中，2026-09-27 核对时共有 23 条。

它不从文章目录提取句子，也不读取独立的 Markdown/JSON 文件。新增短命题不需要生成文章目录或创建文章文件。

## 2. 追加一条字符串

编辑 `thought-tree.js` 中的 `thoughts` 数组，在最后一项后加逗号，并追加一条完整句子。以下是演示写法，只有决定正式使用时才加入项目：

```javascript
    "可见即可解决",
    "示例：每一次观察，都应允许下一次修正。"
];
```

一条命题占一个字符串。中文标点可直接输入；字符串使用英文双引号包围，内容中的英文双引号和反斜杠分别写成 `\"` 与 `\\`。避免把真实换行直接写进普通双引号字符串，也不要漏掉相邻条目之间的逗号。

句子通过 `textContent` 显示，Markdown 的 `**加粗**` 和 HTML 标签不会被当成格式处理。建议一条只表达一个观点，保持适合手机屏幕阅读的长度。当前代码没有限制句子的最大字数；长句需特别查看气泡是否溢出。

## 3. 同步光点数量说明

编辑 `index.html` 中 `id="thoughtNodes"` 的元素。当前为：

```html
<div class="thought-tree__nodes" id="thoughtNodes" role="group" aria-label="树冠上的 23 个思想光点" inert></div>
```

若增加一条，将 `23` 改为 `24`；增加多条或删除时，写入数组的实际条数。保留其他属性，尤其是 `inert`：初始化完成前由脚本控制交互开放，不要为提前显示光点而删除它。

数量文字目前是手写值，脚本不会自动更新。每个光点自己的无障碍标签则由脚本自动生成，形式是“思想 N：句子”。

## 4. 了解自动布局与交互

脚本会按 `thoughts.length` 创建按钮，从树冠粒子中选取位置并分散布局，因此通常不需要手填坐标或修改 `crownLobes`、动画参数、粒子资源、CSS。

数组顺序决定句子与按钮索引的对应关系；具体屏幕坐标会随句子数量、窗口大小和布局重新计算，新增后部分已有光点移动是正常现象。

交互规则是：鼠标悬停或键盘聚焦显示句子，点击固定，再次点击取消固定；Escape 或点击思维树空白处收起。初始化动画尚未完成时按钮禁用，动画结束后开放交互。

代码使用树冠候选粒子布点，数量过多可能变得拥挤；候选粒子不足时还会报 `Insufficient crown particles for the thought nodes.`。因此没有可以直接承诺的无限容量，批量增加时应分批检查布局与可点选性。

## 5. 页面检查与发布

1. 重新打开或刷新本地 `index.html#thoughtTree`，让思维树进入视口，等待初始化动画结束。
2. 逐个查看本次新增的光点，确认显示的是完整原句，不是重复的旧句或示例占位内容。
3. 检查悬停、点击固定、再次点击取消、Escape 收起，以及在不同光点之间切换。
4. 用键盘 Tab 聚焦光点，再用 Enter 或空格触发按钮；检查焦点和句子显示。
5. 在手机窄屏检查新句是否完整、气泡是否遮挡或溢出，光点是否容易点到；如果一次增加多条，尤其检查密集区域。
6. 核对 `thoughts` 条数与 `index.html` 的无障碍数量文字一致。
7. 按 [通用发布步骤](README.md#通用发布步骤) 一起提交 `thought-tree.js` 和 `index.html`。等 Pages 成功后，在 [线上 Mindmap](https://moriatyli.github.io/#thoughtTree) 复查。

## 更新、删除与排错

修改既有命题时只改对应字符串，数量不变则无须改 HTML 数量。删除命题时移除整个条目，检查逗号并同步更新数量。

| 现象 | 排查方向 |
| --- | --- |
| 光点仍是旧句 | 是否修改正确的 `thoughts` 数组、推送并部署，浏览器是否缓存旧脚本 |
| 思维树完全不运行 | 字符串引号、逗号、数组闭合是否正确，检查浏览器报错 |
| 暂时点不到任何光点 | 是否进入视口并等待初始化结束；检查粒子资源是否加载 |
| 句子太长被遮挡 | 先精简为短命题，确需长文时另行调整气泡布局 |
| 屏幕阅读器仍读旧数量 | `index.html` 中的 `aria-label` 是否同步更新 |
| 大量新增后位置拥挤 | 减少单次增量，检查移动端；必要时单独调整布局算法 |

需要模拟时，在独立本地副本中暂加一条带“演示”标记的句子并调整数量，只用于预览；发布前从差异中移除这两处模拟修改。不要把模拟结果误记为正式新增。
